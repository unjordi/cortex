### 🔒 🚧 `git-branch-guard`  ·  PreToolUse/Bash · deny
Wrapper delgado sobre la lib `analizar-comando-git.sh` (`git-branch-guard.sh:22`). Dispara cuando `acg_push_toca_base` da true — push explícito a develop/main **o** push PELÓN/`HEAD`/`--force` estando parado EN develop/main (H1) **o destino OPACO** (`$VAR`/backtick — `acg_push_destino_opaco`, H2 auditoría de ejecución 2026-09-16, MEDIO: `git push origin "$RAMA"` quedaba ciego, simétrico al `--repo "$VAR"` de M9) — o cuando `acg_merge_menciona_base` detecta un merge que nombra la base (`:29`,`:33`). BLOQUEA (deny) y redirige al flujo ramita→MR→develop; a main solo release deliberado (lo vigila merge-develop-guard). No hay escape hatch propio (es una norma dura); la lib **ignora menciones entrecomilladas (H13) y valores de `--repo`/`-R` (H11)** para no dar falsos positivos. Sin comando parseable → `exit 0`. **M7 (auditoría 2026-09-15 §2.3, homologación)**: sin `jq` ya NO es fail-open blanket — greppea el input crudo por `push`/`merge` de MR; si PARECE lo que este guard vigila → DENY (fail-safe); si no, `exit 0` (mismo patrón que el A3 de `confirmar-merge-develop`, ahora homologado). **ALTO-2 (auditoría FMEA 2026-09-16 §1.4, PRECISIÓN)**: el M7 de arriba bloqueaba TAMBIÉN push a tu propia ramita/mini-develop (el camino MÁS transitado) — medido por A/B. **H1 (auditoría semántica 2026-09-16, ALTO, reemplaza el fix original)**: la primera versión (`_m7_push_riesgosa_sin_jq`) razonaba sobre el JSON CRUDO completo — el campo `description` del payload ("Empujar la ramita del MR a develop") bastaba para bloquear una ramita legítima, la MISMA mordida que ALTO-2 quería cerrar. Fix de raíz: extrae SOLO el campo `command` (regex acotada de cadena JSON) y reusa `acg_push_toca_base`/`acg_merge_menciona_base` REALES (ninguna necesita jq) — PARIDAD exacta con el camino con-jq, no una heurística propia; por esa misma paridad, un `mr merge` SIN destino explícito por flag tampoco es cosa de ESTE guard (con o sin jq) — lo siguen gateando merge-squash-guard/confirmar-merge-develop, que bloquean TODO merge sin jq sin cambio (no hay precisión de texto posible ahí: el destino sale de la API). ## 📜 Normas — reglas que Claude se autoimpone (viven en `CLAUDE.md`)

### 📜 🎯 `Definition of Done`
Verde técnico (build/tests/lint + memoria al día) ≠ LISTO/Done/"ya quedó". Algo es LISTO **solo** si (1) el usuario confirmó la funcionalidad (QA visual/funcional o una prueba acordada de antemano) **o** (2) autorizó EXPRESAMENTE el cierre de esa cosa concreta. "sigue/avanza" NO autoriza (solo permite trabajar sin pedir permiso a cada paso); la autorización es ACOTADA y NO transitiva. Lo hacen cumplir `dod-verificar` (al DECLARAR) y `merge-develop-guard` (al INTEGRAR).

### 📜 🪞 `Doc = realidad`
Cambió algo real (config aplicada, ruta, comportamiento, decisión) → su doc se actualiza en la **MISMA tanda**, sin preguntar ("¿actualizo la doc?" no se pregunta, se hace). El orden es revisar el estado real → editar. Rastrea las OTRAS copias (grep del valor/nombre viejo): una sola copia desincronizada ya es doc que miente.

### 📜 🌿 `Flujo de git`
NUNCA `git push` a `develop` ni `main`. Todo va por **ramitas** (`feat/fix/chore/docs`) → **MR/PR** → `develop` (con `--squash`). `main` es **release-only** (deliberado, OK súper-explícito). Modelo **mini-develop por dev** (`Develop<Usuario>`): el día a día itera sin fricción en tu mini; solo el MR mini→develop pasa por el candado (`merge-develop-guard`).

### 📜 💰 `Costo de delegación`
Reclutar un agente cuesta según su nivel (**gratis** local · **incluido** dentro de la ventana 5h · **metered** overage/API de pago/desconocido). Consentimiento window-aware ANTES de delegar; gratis/incluido se pregunta 1×/compu, metered 1×/workflow. Lo piden `delegacion-gate` (pregunta) y `limite-gasto` (freno duro si no hay cupo).
